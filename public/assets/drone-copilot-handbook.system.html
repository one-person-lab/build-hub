数据层 · 不同类型的数据交给合适的存储
  • PostgreSQL会话元数据、任务草稿与版本、正式任务、审计、Outbox（唯一权威状态）
  • Redis会话短期状态、热点缓存、幂等键、限流（会过期，不是任务状态的最终依据）
  • RocketMQ任务执行、遥测处理、告警、报告生成事件（不当实时查询库用）
  • Milvus手册、规则、历史案例的向量（召回只作参考，不判断设备是否在线）
  • MinIO图片、视频、报告附件（对象键与采集时间存在 PG）
  • 基础设施层Java 21 运行环境、容器、网关、日志、监控、密钥与网络（不实现业务逻辑）
异步链路 · 用户点确认之后怎么跑
  1. 任务状态变更与待发布事件写进同一个 PG 事务（outbox_event）
  2. Outbox 再发到 RocketMQ——事务与发消息不是同一个原子操作，靠可靠重试 + 幂等消费兜住
  3. 执行消费者调现有任务服务与设备控制链路下发
  4. 遥测与告警产生事件，消费者回写任务状态
  5. 任务结束发布完成事件，报告服务汇总生成
  6. Copilot 用 SSE 推状态、告警与报告进度
系统边界
  • 模型给的是计划，不是已批准的飞行指令；权限、空域、航线一律由业务服务校验。
  • 权威状态只有一处：PG 里的任务记录。Redis 会过期，SSE 只是通道、不保存状态。
  • 向量召回不能替代实时空域查询；RAG 文档与工具返回都按待验证数据处理。
模型超时或不可用返回明确的规划失败状态，不自动执行。
设备/空域服务超时标记待重试或失败，不把「未查询到」当成「没有限制」。
MQ 积压或重复投递按事件 ID 或业务幂等键去重；积压期间任务状态不变。
SSE 断开用任务查询接口恢复状态，必要时按事件 ID 补取。
