# Paperclip —— AI agent 编排控制面

- 仓库：https://github.com/paperclipai/paperclip
- 收录日期：2026-09-21（以下事实当日核实）
- 协议 / 规模：MIT · TypeScript · Node.js 服务端 + React 界面 · 2026-03 开源，约 81k stars
- 一句话：给一队 AI agent 建"公司"——目标、任务工单、审批、预算、心跳全在一个控制台里管。

## 它是怎么运转的

1. **目标 → 工单**：先定义业务目标（如"$1M MRR"），目标拆成任务卡，卡上带完整目标链，agent 干活时永远看得到"为什么"。
2. **认领原子化**：任务 checkout 是数据库级原子操作，两个 agent 不会做同一张卡。
3. **审批门**：agent 交付要附 diff / 截图 / 测试三类证据，人批准才算完成。
4. **心跳**：周期性工作（报表、客服跟进）由 agent 按日程自动醒来做，不用人kick。
5. **预算熔断**：每 agent 月度 token 预算，用完即停，防跑飞。

## 对我们的参考价值

**搬概念（已在 uni-workbench 认领协议落地）：** 证据门、原子认领、heartbeat 例行卡、卡带目标链。

**不学：** org chart / RBAC / 多组织隔离（公司规模虚构，一人系统不适用）；
它的 server 本体（数据库为真相，与我们「文件即真相」根本对立）。

**触发重估的条件：** 当出现十几个 agent 真正并发抢活、需要跨机调度时，直接引入它当组件，不自研调度层。
